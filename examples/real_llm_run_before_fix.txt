--------------------------------------------------------------------------------
  如何阅读这份记录：四类异常，都是修复的线索
--------------------------------------------------------------------------------

1) Error: LLM HTTP 错误 {"code":20015,"message":"The parameter is invalid..."}
   中文 Windows 上 argv 被按 ANSI 代码页转成 GBK 字节，再按 UTF-8 发出，
   请求体成了非法 UTF-8，接口直接拒绝。当时误以为是提示词写错了。

2) Error: 未能提取到变量  —— 注意 LLM Response 里那行孤零零的 "n"
   剥 ```json 代码块围栏时写成了 b1 + 6，而 "```json" 是 7 个字符，
   于是模型字符串开头永远多一个 "n"，解析自然失败。

3) Error: 求解失败: ERROR
   求解层抛 ValueError，traceback 直接打到 stdout，C++ 侧只看到无法解析的
   内容，于是只知道"失败"，不知道原因。

4) 最后一条 Objective: 0.08
   这是最危险的一条：状态是 success、不抛异常、不打日志，只是答案错了。
   投资题的"500 万资金的最大收益是 8 分钱"在数学上成立，
   但在常识上明显不对——正是这个数字牵出了根本问题：
   目标函数表达式被解析层静默截断。

  注解（以上为原始记录，以下为事后补充）

同一批测试里的三道题，只有投资题被这个 bug 打中：

    工厂题    Objective: 60      —— 正确（目标函数 3*x + 5*y 不触发该 bug）
    背包题    Objective: 8000    —— 正确（同上）
    投资题    Objective: 0.08    —— **错误**（目标函数是混合系数写法，
                                     正则第一条就命中了裸数字 0.08）

修复后，同一个投资模型的离线求解结果是 60.0，对应"500 万全部投入
收益率最高的 B 类（12%）"，与直觉一致。可复现的输出见
examples/demo_transcript.txt 第 1 段。

四类异常的根因、修复方案与验证过程，见 docs/FIXES.md。

要拿到"修复后"的真实调用记录，需要自己配置 SILICONFLOW_API_KEY 后
运行本程序——本项目不再附带任何真实调用日志，以免把个人题目与调用
记录持续写进公开仓库（ADPLANNER_LOG=off 可完全关闭日志）。
